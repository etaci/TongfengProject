# V22 找回密码与账号验证骨架

## 本轮目标

这一轮继续承接账号安全方向，优先补齐两个最基础、最能增强真实信任感的闭环：

- 找回密码
- 账号验证

当前仍然是“可联调、可扩展”的安全骨架，不是最终的医疗级账号体系，但已经把核心交互和后端状态链路打通了。

## 需求优先级

### P1 本轮完成

- 正式账号支持请求验证码并重置密码
- 正式账号支持查看验证状态、发送验证验证码、完成账号验证
- 安全中心展示账号验证状态
- 登录首页补上“找回密码”模式
- 账号验证成功后同步刷新当前会话状态

### P1 下一步建议

- 接入真实短信或邮件投递渠道
- 补邮箱/手机号格式与归属校验
- 增加异常登录提醒、设备指纹、风险拦截
- 从长期 `localStorage token` 逐步迁移到更安全的会话管理方式

## 后端能力

### 找回密码

- `POST /api/v1/auth/verification-codes/request`
  - 用途：请求找回密码验证码
  - 请求体：`purpose=PASSWORD_RESET`、`accountType`、`account`
- `POST /api/v1/auth/password-reset/confirm`
  - 用途：用验证码确认重置密码
  - 请求体：`accountType`、`account`、`verificationCode`、`newPassword`、`confirmPassword`

实现要点：

- 验证码使用独立挑战表保存
- 验证码哈希存储，不明文落库
- 重置密码成功后，原有登录会话会被统一失效
- 对不存在账号的找回请求返回泛化成功文案，避免直接暴露账号是否存在

### 账号验证

- `GET /api/v1/auth/account-verification/status`
  - 用途：查看当前正式账号是否已验证
- `POST /api/v1/auth/account-verification/request`
  - 用途：请求账号验证验证码
- `POST /api/v1/auth/account-verification/confirm`
  - 用途：提交验证码并完成账号验证

实现要点：

- 仅正式密码账号支持该流程
- 验证成功后会刷新当前用户各活跃会话中的 `accountVerified`
- 前端刷新后可以直接展示“已验证”状态

## 前端交互

### 首页登录区

新增第三种模式：

- 账号登录
- 新用户注册
- 找回密码

找回密码模式下支持：

- 选择账号类型
- 输入账号
- 请求验证码
- 输入验证码并设置新密码
- 成功后自动切回登录模式，并带回账号信息

### 安全中心

正式账号登录后，安全中心现在会展示：

- 账号类型
- 账号标识
- 活跃会话数
- 账号验证状态
- 验证完成时间
- 发送验证验证码
- 输入验证码完成验证
- 修改密码
- 移除其他设备会话

## 当前边界

这轮仍然是“真实登录与隐私授权骨架”的继续深化，当前刻意保留了以下边界：

- 还没有接短信/邮件真实供应商
- 验证码目前仍可通过模拟投递模式联调
- 还没有做完整的找回密码频控、风控和设备风险识别
- 还没有做实名、医院统一身份、机构级账户对接
