# V21 化验单可信边界收紧

## 下一阶段需求优先级

基于本轮产品评估，下一阶段先按下面顺序推进：

### P0

- 化验单 OCR 低置信度时必须人工确认
- 阻断估算值进入正式复盘结论链路
- Mock 登录从真实主入口下沉

### P1

- 找回密码与账号验证骨架
- 异常登录提醒、设备标识、会话安全增强
- 用药闭环继续深化：延迟服药、漏服升级、家属跟进、医生可读导出

### P2

- 检查结果导入
- 医患安全消息
- 复查预约 / 病历分享 / 真实医疗连接

## 本轮目标

V21 先解决当前最影响分数的两件事：

- 医疗可信度不够硬
- 正式产品入口仍混入开发体验心智

本轮新增约束：

- 当化验单未稳定识别出关键指标时，系统不再生成估算指标
- 这类报告不会进入正式目标值判断、趋势对比和复盘结论链路
- 前端明确展示“人工确认模式”
- Mock 登录仅在开发环境显示

## 化验单行为变化

### 上传解析后

如果 OCR 能稳定提取指标：

- 正常返回指标列表
- 允许继续查看复盘

如果 OCR 不能稳定提取指标：

- `indicators` 返回空列表
- `manualConfirmationRequired = true`
- `reviewReady = false`
- `extractionStatus = MANUAL_CONFIRMATION_REQUIRED`
- 前端提示重新上传或人工确认

### 查看复盘时

如果报告未达到可复盘条件：

- 返回 `reviewStatus = MANUAL_CONFIRMATION_REQUIRED`
- 不返回指标对比列表
- 不输出目标值结论
- 不输出趋势推演
- 只返回人工确认说明、下一步动作和可信边界

## Mock 入口变化

首页仍保留真实登录和注册。

但开发体验入口现在只在 `Vite` 开发环境显示：

- 开发环境：可见
- 生产构建：不可见

这样正式产品入口不会再直接暴露 `mock-login` 心智。

## 验证结果

本轮已完成：

- 后端 `mvn test`
- 前端 `npm run build`
- AI 服务 `python -m compileall`

并新增后端测试覆盖：

- 空指标报告会进入人工确认模式
- 这类报告列表态会标记 `manualConfirmationRequired`
- 复盘接口不会继续输出正式比较结论

## 当前边界

这一版已经把“估算值伪装成真实结果”的风险压下来了，但还没有做到完整医疗可信体系。

当前仍未覆盖：

- OCR 逐项人工确认表单
- 手动补录关键指标
- 逐指标置信度
- 医疗来源签名 / 医院结果直连
